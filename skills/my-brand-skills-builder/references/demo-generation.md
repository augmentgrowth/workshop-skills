# demo-generation.md — the three demo artifacts

Goal: generate the three artifacts that ship inside the brand folder’s `demos/`.

The PDF shows what voice + design unlock together. The two HTML files
show the design system live (you can open them in any browser, no
install needed).

## Artifact contract

| File | Purpose | Source |
|---|---|---|
| `<Brand>_Brand_In_Action.pdf` | "Here's what the voice and design unlock — four end-to-end examples." | `templates/brand_in_action.md.tmpl` + screenshots of the two HTMLs |
| `brand_showcase.html` | Live design system in a browser. Color palette, type scale, components. | `templates/brand_showcase.html.tmpl` |
| `welcome_email.html` | Live email mockup combining voice + design. | `templates/welcome_email.html.tmpl` |

## Placeholder substitution

All three templates use `{{PLACEHOLDER}}` Mustache-style tokens.
**The templates themselves define the full placeholder set — scan each
template for `{{...}}` tokens first (there are ~45 across the three,
including font-URL, dark/variant color, hero-copy, and email fields) and
populate every one before writing the rendered file.** The tables below
list only the shared core, not the full set. Two gotchas:

- Font `@import`/`<link>` URLs in the templates hardcode weight axes
  (e.g. `:wght@700;900`). If the brand's Google Font doesn't ship those
  weights, Google Fonts silently drops the whole family and the mockup
  falls back to sans. Check the family's real weights and fix the URL.
- The templates carry neutral defaults (gradients, rounded corners,
  dark-on-dark cells). Reconcile every rendered mockup against
  design.md's rules — flatten gradients, square corners, fix contrast —
  before screenshotting. The render-inspect-fix loop is where this gets
  caught.

Placeholders shared across templates:

| Token | Source | Example |
|---|---|---|
| `{{BRAND}}` | brand name input | `Restore Hyper Wellness` |
| `{{BRAND_UPPER}}` | brand name uppercased | `RESTORE HYPER WELLNESS` |
| `{{BRAND_SLUG}}` | lowercased + hyphenated | `restore-hyper-wellness` |
| `{{TAGLINE}}` | from voice guide signature phrases | `Body, mind, performance — restored.` |
| `{{PRIMARY_COLOR}}` | design.md `colors.primary` | `#0066CC` |
| `{{SECONDARY_COLOR}}` | design.md `colors.secondary` (fallback to primary) | `#00A86B` |
| `{{DISPLAY_FONT}}` | design.md `typography.display` | `Alumni Sans` |
| `{{BODY_FONT}}` | design.md `typography.body` | `Inter` |
| `{{AFFIRMATION}}` | voice guide non-negotiables, "Affirmation" line | `I am Strong. I am Brave. I can DO THIS.` |
| `{{SIGNATURE_PHRASE}}` | one signature phrase that fits an email closer | `Helping kids WIN AT LIFE.` |

The brand_in_action template also uses:

| Token | Source |
|---|---|
| `{{CHANNEL_1_NAME}}` | first channel from voice guide cheat-sheet |
| `{{CHANNEL_1_OUTPUT}}` | generated by wrapped voice skill against a prompt for that channel |
| ... `{{CHANNEL_N_OUTPUT}}` | repeat for each channel demoed |
| `{{BEFORE_1}}` / `{{AFTER_1}}` | before/after pair for prompt "rewrite a generic line in our voice" |

For the channel demos and before/after pairs, invoke the wrapped voice
skill against a generated prompt. This produces fresh voice-skill
output rather than canned examples — the demo PDF is generated *by the
shipped skill*, which is the strongest possible demonstration.

## Workflow

```
1. Read voice guide -> extract tagline, affirmation, signature phrases
2. Read design.md frontmatter -> extract colors, fonts
3. Generate channel/before-after outputs by invoking wrapped skill
   (4-6 channel demos + 3 before/after pairs)
4. Substitute placeholders in templates -> demos/
5. Run build_screenshots.py to PNG the HTML mockups
6. Optional: humanizer pass on brand_in_action.md (if that skill is installed)
7. Run build_pdf.py to render the final brand_in_action.pdf
8. Delete the intermediate files (_*.md and embed-only *.png) when done
```

## Why HTML mockups, not just PDF

The START-HERE note points the user at the HTML
files directly in a browser — no install, no AI tool, no Claude
session. They're the lowest-friction demo. The brand_showcase includes
interactive states (hover, focus, active) and palette swatches that PDF
can't show.

The brand_in_action PDF embeds screenshots of these two HTMLs as
visual proof of the design system in action, while the markdown body
explains what voice + design produced for each example.

## Structure of brand_in_action.pdf

1. **Cover page** — branded gradient, headline "Brand in Action",
   prepared-by / prepared-for / date metadata
2. **Page 1 — Multi-channel announcement.** One event/announcement
   written for 6 channels (IG, FB, TikTok, LinkedIn, email, website).
   Each output rendered as a callout blockquote.
3. **Page 2 — Before/after pairs.** Three pairs of generic copy
   rewritten in the brand voice. Side-by-side or stacked depending on
   length.
4. **Page 3 — Brand showcase reference.** Embedded `brand_showcase.png`
   screenshot of the design system mockup. Shows the visual identity
   end-to-end.
5. **Page 4 — Welcome email mockup.** Embedded `welcome_email.png`.
   Shows voice + design combined in an email send.

H1 headings force a page break, so the PDF naturally splits into
these four pages.

## Common failure modes

| Symptom | Fix |
|---|---|
| Embedded PNGs missing in PDF | Re-run `build_screenshots.py` before `build_pdf.py` — PNG paths are referenced absolutely |
| HTML mockup uses wrong color | Re-substitute placeholders; verify design.md primary matches |
| Channel demo outputs sound generic | Wrapped voice skill not loading — confirm SKILL.md ends in `<brand-slug>-voice/SKILL.md`, not double-nested |
| Cover gradient looks bland | `--brand-secondary` missing from design.md frontmatter; degenerates to flat primary |
| Webfonts don't load in PDF | Playwright didn't wait long enough; the 2500ms timeout in build_pdf.py is usually enough but slow connections may need more |
